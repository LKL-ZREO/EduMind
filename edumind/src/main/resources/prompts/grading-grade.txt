【批改指引】

一、内容匹配检查
1. 首先判断学生提交的内容是否与上述【老师布置的作业要求】相匹配
2. 如果完全不匹配（学生提交了错误题目/无关内容），在 overallComment 中明确指出
3. 如果不匹配，totalScore 不得超过 30 分，contentScore 不得超过 15 分

二、评分体系

总分与等级（maxScore 固定为 100）：
| 等级 | 分数区间 |
|------|---------|
| A    | 90-100  |
| B    | 80-89   |
| C    | 70-79   |
| D    | 60-69   |
| F    | 0-59    |

评分维度（按作业类型自动适配）：
1. 内容正确性（contentScore，满分 70 分）
   - 编译是否通过（C语言：无法编译 → 总分 ≤ 40）
   - 需求完成度：是否实现所有要求功能
   - 输出正确性：给定输入是否产生正确输出
   - 边界处理：边界条件、异常输入是否处理
   - 内存安全：是否存在内存泄漏、野指针、缓冲区溢出
   - 算法效率：时间/空间复杂度是否合理

2. 代码规范（formatScore，满分 30 分）
   - 命名规范：变量/函数命名有意义（拼音命名、a/b/c 等无意义命名扣分）
   - 缩进与格式：缩进一致、大括号风格统一
   - 注释：关键逻辑有注释说明
   - 结构清晰：函数拆分合理，无过长函数（> 80 行扣分）

三、扣分准则

原则：不影响功能的轻微问题只扣少量分，严重影响功能的错误要扣重分。

分级扣分标准：
| 级别 | 单次扣分 | 示例 |
|------|---------|------|
| 致命(critical) | 10-20 分 | 无法编译、核心逻辑完全错误、程序崩溃 |
| 主要(major)   | 5-10 分  | 输出结果错误、内存泄漏、数组越界、未实现要求功能 |
| 轻微(minor)   | 1-3 分   | 命名不规范、缺少注释、缩进不统一、变量未初始化但无后果 |

典型场景：
- 代码无法编译 → 总分 ≤ 40
- 编译通过但运行崩溃 → 总分 ≤ 50
- 核心功能未实现 → contentScore -20
- 输出结果错误（多数用例失败） → contentScore -10~15
- 内存泄漏（malloc 后无 free） → contentScore -5
- scanf 未取地址 & → contentScore -5
- 数组越界风险 → contentScore -5
- 使用未初始化变量 → contentScore -3~5
- = 错写 == 或反之 → contentScore -5
- 无 return 语句（非 void 函数） → contentScore -3
- 变量命名无意义（a, b, x, temp1） → formatScore -2
- 拼音命名 → formatScore -1
- 缩进混乱 → formatScore -1~2
- 缺少关键注释 → formatScore -1~2

扣分上限：
- 同一类 minor 问题最多扣 3 次
- contentScore 最低为 0，formatScore 最低为 0
- totalScore = contentScore + formatScore，最低为 0
