【建议生成指引】

一、优先级（suggestions[].priority，必须从以下选择）
| priority | 含义 |
|----------|------|
| high   | 影响功能或安全，必须修复 |
| medium | 影响代码质量，建议修复 |
| low    | 锦上添花，可选修复 |

二、issue 格式
使用模板："{类别} - {问题概要}"
类别词可选：内存管理、输入验证、代码结构、算法逻辑、代码规范、错误处理、边界检查

三、知识点关联（重要）
- 每个 suggestions[] 必须携带 knowledgePoint 字段
- 值从上下文的教师定义知识点列表中选择
- 若无法匹配任何知识点，填 "其他"
- 纯建议类（无对应错误）则按建议内容归类

四、建议质量要求
- 针对每条错误或不足，生成具体的、可操作的行动建议
- 建议应该是学生可以立即执行的行动，而非泛泛而谈
  ✗ 错误示例："多练习指针"
  ✓ 正确示例："练习使用 malloc/free 配对管理内存，尝试写一个动态数组的完整示例"
- 按问题严重程度组织建议，high 优先级的建议排在前面
- 如果评分结果良好（≥85 分），可减少建议数量，侧重进阶提升

请严格输出以下 JSON 格式：

{
  "suggestions": [
    {
      "issue": "对应的问题（格式：{类别} - {问题概要}）",
      "suggestion": "具体的学习建议（可执行的行动描述）",
      "priority": "high/medium/low",
      "knowledgePoint": "归属知识点（从上下文知识点列表选择，无法匹配填"其他"）"
    }
  ]
}

⚠️ 重要：
- 只输出纯 JSON 对象，不要用 ```json 代码块包裹
- 不要输出任何解释文字、前缀或后缀
- 所有字段必须出现，suggestions 可以为空 [] 但不能为 null
- knowledgePoint 字段必须填写，不可省略
- 建议要具体可操作，禁止"多练习""多看书"等空泛表述
- 确保 JSON 完整，不要截断
