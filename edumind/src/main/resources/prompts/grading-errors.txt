【错题分析指引】

一、错误类型（errors[].type，必须从以下选择）
| type | 说明 |
|------|------|
| 语法错误 | 无法编译通过的错误 |
| 逻辑错误 | 编译通过但输出/行为不正确 |
| 内存错误 | 内存泄漏、野指针、越界、重复释放 |
| 指针错误 | 空指针解引用、指针类型不匹配 |
| 输入输出 | scanf/printf 格式错误、文件操作错误 |
| 规范问题 | 命名、缩进、注释等规范性问题 |
| 安全问题 | 缓冲区溢出、格式化字符串漏洞 |

二、严重程度（errors[].severity，必须从以下选择）
| severity | 含义 | 扣分范围 |
|----------|------|---------|
| critical | 致命，导致无法编译或运行崩溃 | 10-20 |
| major    | 主要，影响功能正确性 | 5-10 |
| minor    | 轻微，不影响功能但需改进 | 1-3 |

三、知识点分类规则（重要）
- 每个 errors[] 必须携带 knowledgePoint 字段，值为教师定义知识点名称或 "其他"
- 如果上下文提供了教师定义知识点列表：将错误匹配到最相关的知识点；匹配不到归为 "其他"
- 如果未提供或列表为空：所有 knowledgePoint 统一设为 "其他"
- 禁止凭空创建上下文中未列出的知识点

四、issue 格式
使用模板："{类型} - {具体描述}"
示例：
- "内存错误 - 第15行 malloc 分配的内存未在函数返回前 free"
- "逻辑错误 - 冒泡排序内层循环边界应为 n-i-1 而非 n-1"
- "规范问题 - 变量名 avgScore 写成了拼音 pingJunFen"

五、其他要求
- 仔细分析"不足"中的每一条，拆解为具体的错误项
- 如果评分结果显示满分或接近满分（≥95），且无明显不足，errors 可以为空数组
- 每条错误需要精确到行号（如无法确定填 0）

请严格输出以下 JSON 格式：

{
  "errors": [
    {
      "line": 行号(整数，如无法确定填0),
      "type": "错误类型(语法错误/逻辑错误/内存错误/指针错误/输入输出/规范问题/安全问题)",
      "issue": "具体问题描述（格式：{类型} - {具体描述}）",
      "severity": "critical/major/minor",
      "knowledgePoint": "归属知识点（从上下文知识点列表选择，无法匹配填"其他"）"
    }
  ]
}

⚠️ 重要：
- 只输出纯 JSON 对象，不要用 ```json 代码块包裹
